# Anatomy of a Generated Skill

This page shows what `aptitude create` actually writes to disk, file by file. The example below is a real, captured run — not invented. Command:

```bash
python -m aptitude create -p "Skill for writing conventional commit messages" \
    -i octocat/Hello-World --provider ollama --model mistral-small:latest \
    --format all --out ./out
```

`octocat/Hello-World` is used instead of a local `.md` file because `detect_kind()` (`aptitude/ingest/base.py`) only recognizes `.pdf`, `.epub`, `http(s)://` URLs, and bare `owner/repo` GitHub shorthand — a raw `.md` path raises `IngestionError`. One honest caveat: that repo's `README` is a single line, `Hello World!`, so almost none of the generated body below came from the ingested corpus — it came from the model's own knowledge of the requested topic. Treat the prose content as illustrative of *shape*, not of what a real source-grounded run produces; the file layout, frontmatter, and exporter behavior are exactly what you get every time.

## The directory

`--out ./out` (the default) puts every format's output under one flat directory named after the generated skill:

```text
out/
└── write-conventional-commit-messages/
    ├── SKILL.md                                   # claude-skill  (aptitude/export/claude_skill.py)
    ├── references/
    │   └── source-material.md                     # claude-skill  (writes draft.references here)
    ├── write-conventional-commit-messages.md       # generic-prompt (aptitude/export/generic_prompt.py)
    ├── write-conventional-commit-messages.json     # generic-prompt (same content as the .md, as JSON)
    ├── Modelfile                                   # local-llm     (aptitude/export/local_llm.py)
    └── system.txt                                  # local-llm     (same content as Modelfile's SYSTEM block)
out/write-conventional-commit-messages.zip           # zip          (aptitude/export/packager.py)
```

Two things worth noting, both confirmed on this exact run:

- **No `mcp.json`.** `--format all` includes `mcp-manifest`, but it wrote nothing. `aptitude/export/mcp_manifest.py:9` is `if not draft.tools: return []` — the exporter returns before creating a directory or a file. Nothing in this codebase currently populates `draft.tools`, so `mcp-manifest` never produces output (see [limitations](../limitations.md)).
- **The zip is a sibling, and it isn't scoped to `claude-skill`.** `zip`'s exporter (`aptitude/export/packager.py`) calls `ClaudeSkillExporter().export(...)` and then zips *everything already in* `out/<skill-name>/` with `skill_dir.rglob("*")`. Because every format in `--format all` writes into that same flat folder, and `zip` runs last in registration order, the resulting archive on this run contained the Modelfile, `system.txt`, and the generic-prompt `.md`/`.json` too — not just `SKILL.md` and `references/`. Verified by listing the real zip's contents: `write-conventional-commit-messages/{Modelfile,SKILL.md,system.txt,write-conventional-commit-messages.json,write-conventional-commit-messages.md,references/source-material.md}`. If you only want the Claude Skill files in the archive, run with `--format zip` alone rather than `--format all`.

## SKILL.md

The real file, in full:

```markdown
---
name: write-conventional-commit-messages
description: "Use when you need help crafting a conventional commit message."
---

To create a skill for writing conventional commit messages, we need to provide
clear, actionable instructions that an AI assistant can follow...
[body continues — full instructional markdown generated by the model]
```

Frontmatter is built by `_yaml_scalar()` in `aptitude/export/claude_skill.py`: it collapses the description to a single line and JSON-encodes it as a quoted YAML scalar (so embedded newlines or quotes stay safe). The body is `draft.body` written verbatim after the frontmatter.

`aptitude validate` (`aptitude/validate/validator.py`) enforces exactly three rules on this frontmatter plus one soft check:

1. `name` must match `^[a-z0-9]+(-[a-z0-9]+)*$` and be ≤ 64 characters. (`write-conventional-commit-messages` is 34 characters, lowercase, hyphen-separated — passes.)
2. `description` must be non-empty.
3. `description` must be ≤ 1024 characters.
4. Soft check, not enforced: if `len(draft.body) < 40`, validation still succeeds but returns the warning `"body is very short; skill may be low quality"` (`validator.py:26-27`). This run's body is thousands of characters, so the warning did not fire here — the CLI would print it as `warning: body is very short; skill may be low quality` after `created '<name>' → N files in <out>` if it had (`aptitude/cli.py:68-69`).

## references/

`ClaudeSkillExporter.export()` (`aptitude/export/claude_skill.py:23-27`) writes every entry in `draft.references` (and `draft.scripts`, currently always empty — see [limitations](../limitations.md)) to `<relpath>` under the skill directory. What populates `references` differs by synthesizer:

- **`template`** (the synthesizer used above, and the default) makes exactly one dedicated LLM call — `prompts.reference_prompt()` — that distills the whole corpus into a single file, always at the fixed path `references/source-material.md` (`aptitude/synthesize/template_synth.py:24,27`). One call, one file, every run.
- **`agentic`** has no such fixed call. Its `add_reference` tool (`aptitude/synthesize/agent_tools.py:12-14,51-58`) lets the model save zero or more distilled files at whatever relative path it chooses, whenever it chooses to during the agent loop. Paths are sanitized against `..` segments, absolute paths, and Windows drive letters, but the number of files and their names are the model's call, not a fixed pipeline step.

## The other formats

### generic-prompt
Emits `<skill-name>.md` and `<skill-name>.json`, both carrying the same `system_prompt` string: description, then body, then (if any references exist) a `## Reference material` section with every reference file inlined (`aptitude/export/generic_prompt.py`). Pick this when you want to paste a skill into an LLM chat surface that has no notion of Claude Skills, Modelfiles, or MCP — just plain portable text, in both human-readable and machine-readable form.

### local-llm
Emits `Modelfile` (Ollama's model-definition format) and `system.txt`. Both wrap the *identical* system prompt used by `generic-prompt` — `local_llm.py` imports `_system_prompt` straight from `generic_prompt.py` (`aptitude/export/local_llm.py:3,10`). It is not a smaller or context-window-trimmed variant; only the packaging differs. One quirk visible in the sample: the `Modelfile`'s `FROM` line is the hardcoded literal `llama3.1`, regardless of which model you actually ran with (this run used `mistral-small:latest`) — you'll need to edit that line before `ollama create` if you ran with a different base model. Pick `local-llm` when you're deploying to Ollama or another local-model runtime (LM Studio, etc.) that expects a system-prompt file or model definition rather than a one-off paste.

### mcp-manifest
Emits `mcp.json` — an MCP tool manifest — but only `if draft.tools` is non-empty (`aptitude/export/mcp_manifest.py:9`). As of today nothing populates `draft.tools`, so in practice this format produces no output at all on any run, as demonstrated above. Pick it once a synthesizer exists that fills in `draft.tools`; until then, selecting it is a no-op.

### zip
Runs the `claude-skill` export, then archives the entire `out/<skill-name>/` directory into `out/<skill-name>.zip` (`aptitude/export/packager.py`). Because it archives whatever is already on disk in that directory rather than just the files it itself wrote, running `zip` alongside other formats (e.g. via `--format all`) bundles their output too, as shown above. Pick it when you want one file to hand off — upload to Claude's Skill Builder, attach to an email or chat message — instead of a directory.

## Checking a skill

```bash
$ aptitude validate ./out/write-conventional-commit-messages
valid
$ echo $?
0
```

And the failure path, constructed here to show the other exit code (not from a real generation — a hand-written `SKILL.md` with an invalid name):

```bash
$ aptitude validate ./bad-skill
invalid: invalid skill name 'Bad Name!'
$ echo $?
2
```

`aptitude validate` exits `0` for a valid skill directory (printing `valid`, plus any warnings) and `2` for an invalid one (printing `invalid: <reason>`), per `aptitude/cli.py`'s `validate` command.
